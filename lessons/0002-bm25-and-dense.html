一句话也可以直接做 BM25 搜索

本课目标：理解分词、倒排索引和评分如何合作，区分它们与 Embedding。

先分清两条链路

Dense：文本 → Embedding 模型 → 稠密向量 → 向量相似度搜索
BM25：文本 → 文本分析与分词 → 倒排索引候选 → 统计相关性评分

Embedding 是生成向量的过程；Dense 指稠密向量表示，Dense Retrieval 指用这种向量搜索。Embedding 模型还可能输出 Sparse 或多个向量，因此两者并不等同。

准备教材

每个 Chunk 的标题和正文经分词、规范化，生成检索词。下表只是示意，具体结果取决于中文 analyzer 配置。

词包含它的 Chunk
分数A、B、C
除法A、C
倒数A、D

这是倒排索引：从词找到包含它的片段，避免每次逐篇扫描。

收到问题

“分数除法为什么要取倒数？”
→ 搜索引擎分析句子（示例保留词：分数、除法、倒数）
→ 按查询匹配规则取得候选
→ BM25 根据词频、词的稀有程度和片段长度评分
→ 返回 TopN

你可以将整句话传给 ES 的 match 查询。独立的关键词提取模型不是必需环节。分词、停用词、同义词等由 analyzer 配置决定，不能假定所有疑问词都会自动被删除；条件词也不应盲目丢弃。

用户只说“为什么错了”时，需要先结合当前题目和错因形成有信息的检索句子。Query Builder 补的是教学意图，这和搜索引擎把句子分成词是不同职责。

ES 还是 VikingDB？

ES 明确支持 BM25 和丰富的 analyzer、查询控制。VikingDB V2 官方关键词接口也提供 mode="bm25"，要求配置 FullText，不能将这个模式与学习型 Sparse Embedding 混为一谈。

HP 已有 ES 时，ES BM25 + VikingDB Dense 可作为可控基线。若目标是少维护索引，可测试 VikingDB FullText BM25 + Dense，在相同 Chunk、过滤、融合和重排条件下比较。国内账号实际能力以具体版本为准。
