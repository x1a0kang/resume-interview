# 08｜慧批项目简历表述与事实边界

> 最后更新：2026-09-09。  
> 本文同时保留“当前可投递稿”和“假设 Agent/RAG 已完成后的目标稿”，两者不能混用。

## 1. 最终包装结论

### 1.1 简历上合成一个主项目

HP-Grading、xEduAI、ChatBI 不是三个互不相关的项目，而是同一套作业产品的三个核心服务模块：

```text
HP-Grading：业务中台、领域数据、任务状态、权限与异步编排
xEduAI：OCR、题目结构化、答案解析、作答识别与批改算法平台
ChatBI：作业、学生、班级、教师、学校、区域的学情分析与报表
```

如果 Agent/RAG 后续真实完成，即使 Python AI 服务独立部署，简历中仍应合并到同一个主项目，形成完整的产品演进：

```text
确定性图片批改 Workflow
→ 确定性学情聚合与报表
→ 多角色 Agent 交互与任务编排
→ 教学资源 RAG 知识增强
```

推荐项目名：

> **慧批 AI 作业批改与智能学情平台**

不建议单独写成“HP-Grading 项目”“ChatBI 项目”“RAG 项目”。仓库和微服务的拆分是工程边界，不等于简历项目边界。拆开会割裂同一条数据链路，也会让 Agent/RAG 看起来像脱离真实业务的 Demo。

只有当 AI 服务已经面向多个产品复用，拥有独立用户入口、发布节奏、知识库和平台团队时，才适合再单列为“企业级教学智能助手平台”。

## 3. 当前可投递版本：Agent/RAG 尚未真实完成

### 3.1 项目简介

面向中小学纸质作业场景的 AI 批改与学情分析平台。HP-Grading 负责教师定标、学生批改、领域数据与任务状态，通过 RabbitMQ 编排 xEduAI 完成 OCR、题目结构化、答案解析、作答识别及逐空/作文批改；ChatBI 在批改结果之上形成作业、学生、班级、教师、学校和区域多层级分析。

### 3.2 当前可写的核心职责

1. **主导业务中台建设：** 基于 Spring Boot 对作业、图片、题目、blank、学生作答和评分结果进行领域建模，覆盖教师定标、答案/解析/分数修订、普通题与作文批改、答题卡及重批等业务闭环。
2. **构建异步 AI Workflow：** 通过 RabbitMQ 解耦 Java 业务服务与 Python 算法平台，分阶段编排 OCR、题目解析、答案解析、解题、作答识别和批改；使用 `requestId + version + 状态机` 关联任务并拦截过期回调。
3. **完善长耗时任务可靠性：** 结合请求持久化、手动 ACK、失败重试、XXL-Job 补偿、异常通知和 Prometheus 指标，支持跨服务任务追踪、故障定位与局部恢复。
4. **参与多模态算法平台设计与开发：** 与算法工程师协同定义题目/blank/作答/评分数据协议和业务规则，参与 OCR、题目结构化、答案识别、逐空及作文批改链路联调，形成规则、OCR、VLM、LLM 协同的处理流程。
5. **主导多层级学情分析平台：** 建设单次作业题目/学生分析、学生与班级周报、教师/学校/区域统计及作文分析，结合异步聚合、大模型建议和 PDF/Excel 产物，为教学讲评和管理看板提供统一统计口径。
6. **完成 AI 应用层演进设计：** 基于现有批改 Workflow 与 ChatBI 分析数据，设计教师、学生、家长多角色 Agent 及教学资源 RAG，明确按钮 Workflow、自由对话 Agent、高层 Domain Tool、权限校验、混合检索、引用和评测边界。

第 6 条必须保留“设计”字样。未完成开发前，不能写“使用 LangGraph 落地”“上线 RAG”或编造任务完成率、召回率、时延和成本收益。

## 4. 假设 Agent/RAG 已完成后的目标稿

### 4.1 项目名称与角色

**项目名称：** 慧批 AI 作业批改与智能学情平台  
**个人角色：** 后端 / AI 应用负责人（最终按真实职级调整）

### 4.2 项目简介

面向中小学作业场景的 AI 批改、学情分析与教学助手平台。系统通过 Java 业务中台和 RabbitMQ 编排 Python 算法平台完成纸质作业的 OCR、结构化、作答识别及逐空/作文批改，由 ChatBI 形成多层级学情统计；在此基础上建设独立 Python AI 应用层，通过多角色 Agent 组合领域数据、题库推荐和教学资源 RAG，为教师生成讲评与备课草案，为学生提供已批改题目的个性化答疑，为家长生成学习报告与计划。

### 4.3 完整简历条目

1. **主导批改与学情平台建设：** 负责 HP-Grading 和 ChatBI 的架构、开发与维护，完成“定标—识别—批改—分析—报告”业务闭环；与算法工程师协同设计和开发 xEduAI，定义跨模块数据协议及核心批改规则。
2. **构建跨语言异步 AI Workflow：** 通过 RabbitMQ 编排 OCR、题目结构化、答案解析、作答识别和逐空/作文批改，使用 `requestId + version + 状态机` 处理任务追踪、回调乱序、幂等重试和异常恢复，并通过 Prometheus 观测各处理阶段。
3. **建设确定性学情分析层：** 基于批改事实实现题目正确率、错题/知识点、学生学习状态、班级周报及教师/学校/区域分析，以异步任务和分层聚合统一统计口径，并支持大模型建议及 PDF/Excel 报表。
4. **落地多角色 Agent：** 使用 FastAPI、LangChain/LangGraph 构建独立 AI 应用层；明确任务按钮携带 `actionCode` 直接进入 Workflow，其余自由文本统一进入 Agent，由 LangGraph checkpoint 维护跨轮目标与约束，并按角色和页面上下文动态开放高层 Tool。
5. **封装受控 Domain Tools：** 将 ChatBI 的班级/学生分析、HP 的作业/题目/批改事实、题库推荐及草案/文件产物收敛为 10 个高层 Tool；在 Tool 执行端重新校验教师—班级、家长—孩子和学生本人数据域，第一期不开放答案、分数和批改结果修改能力。
6. **落地教学资源 RAG：** 对授权教材、教参和辅导资料建设解析、OCR、语义分块、Embedding、版本与索引 Pipeline，使用独立教学资料 Collection 完成 BM25 + Dense 混合召回、元数据过滤、Rerank 和 Evidence Pack，为讲评、课本化答疑和备课提供可追踪引用。
7. **建设 Agent/RAG Harness：** 通过结构化 Tool Schema、调用上限、超时重试、幂等、Trace、审计和离线 Evaluation Harness，验证工具选择、最终领域状态、权限越界、检索相关性、资料版本、引用忠实度和异常恢复。

### 4.4 一页简历压缩版

1. 主导 Spring Boot 批改业务中台与 ChatBI 学情分析服务，完成定标、识别、逐空/作文批改及学生、班级、教师、学校、区域多层级分析；协同算法工程师设计开发 Python 算法平台。
2. 通过 RabbitMQ 编排 OCR、题目解析、答案生成、作答识别和批改流程，以 `requestId + version + 状态机` 处理任务追踪、回调乱序、幂等重试和异常恢复。
3. 基于 FastAPI、LangChain/LangGraph 建设多角色 Agent，采用“按钮直达 Workflow、自由文本进入 Agent”的双入口，通过 checkpoint 续接多轮任务，并将业务能力收敛为按角色动态开放的高层 Domain Tools。
4. 建设教材、教参和辅导资料 RAG，完成文档解析、语义分块、Embedding、BM25 + Dense 混合召回、元数据过滤、Rerank 与 Evidence Pack，为讲评、答疑和备课提供教学证据。
5. 将业务事实、题库推荐与教学资料检索分层，并以服务端权限校验、Trace、审计和离线评测覆盖工具选择、数据越权、检索质量、引用忠实度及异常恢复。

## 5. Agent/RAG 的真实架构口径

### 5.1 入口不再设置独立意图分类

```text
明确任务按钮
→ actionCode + 页面上下文
→ 确定性 Workflow

任意自由文本
→ 当前角色 Agent
→ 根据问题追问或调用 Domain/RAG/Recommendation/Artifact Tool
→ observation
→ 判断继续调用、总结或结束
```

不再建设廉价意图模型、分类模型、Pattern Router 或 `PendingRoute`。信息不足时由 Agent 生成追问，`messages + activeGoal + knownConstraints + toolObservations` 保存到 LangGraph checkpoint；下一轮使用同一 `threadId` 恢复状态。

### 5.2 ChatBI 是分析 Tool 的主要数据层

Agent 不应从 HP 全量原始批改记录重新计算所有统计：

| Agent 能力 | 首选事实来源 |
| --- | --- |
| 教师单作业/多作业班级分析 | ChatBI `HwAnalysis`、`ClassWeekAnalysis`，HP 补题目和错因明细 |
| 家长孩子学习报告 | ChatBI `StudentWeekAnalysis`，HP 补已批改题目详情 |
| 学生单题答疑 | HP 题目、标准答案、解析、学生作答和逐空批改结果 |
| 班级对比、正确率和难度 | ChatBI 确定性聚合，禁止 LLM 自行计算 |
| 典型作答 | HP 批改明细 + ChatBI 分组结论，服务端筛选和裁剪 |
| 教学解释与教材出处 | 教学资源 RAG |

趋势仍不单独建立 `get_class_learning_trend` Tool。`get_class_homework_analysis` 返回按时间排列的确定性指标、必要数值差值、样本量和数据质量，模型负责解释改善、下降、偶发变化或证据不足。

### 5.3 技术栈

```text
既有领域与分析服务：Java 8、Spring Boot 2.3
AI 应用服务：Python 3.12、FastAPI、Pydantic v2
Agent：LangChain Core / create_agent、LangGraph、Checkpointer
RAG：文档解析/OCR、Embedding、BM25 + Dense、Reranker、VikingDB
数据与基础设施：MySQL、MongoDB、Redis、Elasticsearch、RabbitMQ、对象存储
治理与评测：OpenTelemetry/Langfuse、pytest、自定义 Evaluation Harness
```

Java 继续拥有领域事实、权限、事务和既有 Workflow；Python 服务承载 Agent/RAG 编排。二者通过受控内部 API 交互，Agent 不直连业务数据库、不直接操作 MQ，也不把现有 Controller 原样暴露给模型。

## 6. 没有量化数字时如何证明做过

简历可以不写未经验证的使用人数、消息量或提升比例，但面试必须能展示以下工程证据：

- Agent Graph 的 State、循环条件、checkpoint 恢复和最大调用次数；
- 10 个 Tool 的输入输出 Schema、角色可见范围、权限校验与错误码；
- 一次教师讲评、学生答疑、家长报告/计划的完整 Trace；
- 文档、版本、chunk、索引、ACL 与 citation 数据模型；
- Hybrid Retrieval、融合排序、Rerank 和无证据拒答的执行顺序；
- 覆盖正常、缺参、越权、工具超时、资料删除/换版和引用错误的离线测试集。

有真实数据后再补任务完成率、Tool 调用成功率、P95 时延、单次成本、Recall@K/MRR、ACL 违规数、citation precision、groundedness 和用户采纳率，不能预估后写入简历。

## 8. 简历页数与新版结构

### 8.1 页数结论

4—5 年经验没有强制只能一页。对于只有一段经历、项目较少的候选人，一页可以成立；对于拥有两段工作经历、多个真实生产项目，并同时投递 Java 后端与 AI 应用岗位的候选人，两页更合适。当前简历新增慧批工作经历后，最终采用两页，不再通过缩小字号和压缩页边距维持一页。

旧简历结构审查显示：文档虽然是一页 A4，但页边距设置为 0，绝大多数正文使用 9 磅字体，并依赖浮动文本框排版；项目经历文本框约占页面 15.3 cm 高度。正文没有进入普通 Word 段落，存在招聘系统解析遗漏、顺序错乱或兼容层重复读取的风险。新版应使用普通段落和稳定的两栏信息结构，不继续沿用全页文本框模板。

### 8.2 推荐两页内容分配

#### 第一页：当前竞争力

1. 姓名、联系方式、目标方向与真实累计年限；
2. 3—4 行职业概述：Java 后端、AI Workflow、Agent/RAG 应用能力；
3. 精简技术栈：Java 后端、AI 应用、数据与消息、工程治理四组；
4. 当前公司工作经历，只写岗位范围与总体职责，避免重复项目细节；
5. 主项目“慧批 AI 作业批改与智能学情平台”，保留 5—6 条最强内容。

第一页必须独立成立：招聘方即使不翻页，也能看到当前岗位、核心技术、业务规模和慧批项目的主要难点。

#### 第二页：过往证据

1. 东方财富工作经历的团队、职责和代表性荣誉；
2. 妙想大模型智能助手，保留 Agent、SSE、多轮会话、存储和真实用户数据；
3. 智能在线客服，保留 Redis 分布式协调和 Kafka 吞吐优化；
4. 资讯推荐接口，保留 ClickHouse 选型、Kafka/Flink 流处理与数据规模；
5. 教育背景与证书压缩到页面底部。

### 8.3 应删除或压缩的旧内容

- 删除工作经历中对各项目的长段重复介绍，项目细节只在项目经历出现一次；
- 个人跑鞋小程序不再作为核心模块，除非投递全栈/产品型岗位，否则删除或压缩为一行；
- 软件设计师证书与教育背景压缩到第二页底部；
- 技能栏删除 SVN、Gradle 等区分度低的工具，以及不能深入回答的“了解”型技术堆叠；

### 8.4 两类岗位的内容取舍

**Java 后端版：** 慧批重点保留领域建模、RabbitMQ 异步编排、`requestId + version + 状态机`、多存储、可靠性和 ChatBI 聚合；Agent/RAG 未实现时只保留一条方案设计。

**Agent/RAG 应用版：** 慧批保留异步 Workflow 底座，突出多角色 Agent 与教学资源 RAG 的产品判断和架构设计；第二页保留妙想项目作为已经上线的 Agent 开发证据。未在 HP 实现的能力仍不能写成已上线成果。
