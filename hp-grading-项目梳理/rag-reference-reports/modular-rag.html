MODULAR-RAG-MCP-SERVER

从 PDF 入库到 MCP 检索响应，拆解模块、算法与可复用的工程契约。

审阅日期 2026-10-15依据 本地源码未启动项目 启动结论是按说明文件与当前电脑环境判断
先看白话版：它把 PDF 文件切成小段并保存，然后可以按关键词和意思查找相关段落。重点是“找到资料并交给 AI 助手”；它不是开箱即用的聊天网站。

项目定位与阅读结论

它是一个面向 MCP Host 的知识检索服务，核心交付是可引用的检索片段。在线 query_knowledge_hub 路径把候选片段、来源和可选图片返回给 Host；这条路径没有服务内的最终答案生成。LLM 主要用于离线 Chunk 精炼、元数据补充、图片描述，以及可选的 LLM Rerank。

适合学习：组件契约 → 双路召回 → RRF → 重排 → Trace → 评测。HP 应借用检索内核，把生成与教学任务放在自己的 Workflow / Agent 中。

Chunk 身份：写入阶段还会重新计算 ID

DocumentChunker 的初始 ID 是 doc_id + 序号 + 原文本短哈希；最终 VectorUpserter 重新用 source_path 短哈希 + 序号 + Transform 后文本短哈希生成存储 ID。Pipeline 将 BM25 的 chunk_id 对齐到返回的向量 ID，双路才能合并。

稳定指“相同路径、序号和最终内容”产生相同 ID。换文件路径、LLM 精炼内容漂移或分块序号变化均会改变 ID；它不是跨重建稳定的业务主键。HP 应独立逻辑 Unit ID、版本内 Chunk ID 和内容 hash，Trace / 标签绑定具体版本。

RRF：融合名次，不代表置信度

实现公式为 score(d) = Σ 1 / (60 + rank(d))，rank 从 1 开始。它让 BM25 与向量召回可以按名次融合，避免直接相加异质分数。两路第一的上界约为 0.032787；仅一路第一约为 0.016393。这个值不是答案正确概率。

0 表示该路未召回

Trace、评测与实际能力边界

能力代码中的现状对 HP 的意义
阶段 Trace记录 load / split / transform / embed / upsert，以及查询、融合、重排等阶段；本地 JSONL 和 Streamlit 展示。借鉴阶段快照，保留候选 ID、原始分、配置版本与失败原因；生产接入既有 Trace 平台。
评测 HarnessEvalRunner 支持注入答案生成器与人工答案 override；未注入时使用片段拼接兜底。必须标注“检索评测”还是“最终生成评测”，不能把拼接答案当作生产模型效果。
Golden Set提供五条样例问题，但 expected_chunk_ids / expected_sources 为空。可参考数据格式；这些样例无法证明真实 Hit Rate / MRR。
Provider 扩展内置实际 splitter 为 recursive，向量实现为 Chroma；注释列出 semantic / Qdrant 等方向。只给已经注册并可加载的实现开配置，启动时校验未知 provider。
依赖收口PdfLoader 可选依赖 PyMuPDF / Pillow；pyproject 的基础依赖未单独列明这两项，Cross-Encoder 所需包也需核对。建立 parser / rerank extras、锁定依赖，做启动与离线降级检查。

不能直接照搬的实现

  • 图片关联：PdfLoader 把图片占位符追加到文本末尾，没有保真地建立图、正文、例题的版面关系；数学教材要保留 ContentBlock 坐标与 assetRefs。
  • 原文与精炼：ChunkRefiner 生成新的 refined_text 写入 Chunk.text；HP 必须独立保存 sourceContent，检索副本只能追加上下文，不能覆盖证据原文。
  • 幂等作用域：SQLite 的主键为 file_hash，should_skip 只查 hash。同一文件换 collection 也可能被跳过；模型或分块版本变化时不能只靠文件哈希决定跳过。
  • 故障语义：工具的 _perform_search 捕获异常并返回 []，可能把检索失败变成“无相关结果”。HP 应返回结构化的 NO_EVIDENCE / DEGRADED / TIMEOUT / DEPENDENCY_ERROR。
  • 过滤位置：Dense 传入 filters；HybridSearch 的 Sparse 路径主要提取 collection，并有融合后过滤。不能据此认为多租户授权已完成，也会有先截断再过滤导致候选不足的问题。
  • 超时：future.result(timeout=30) 不等于底层 HTTP / 数据库调用被取消；ThreadPoolExecutor 退出仍可能等待工作结束。要配置依赖超时与请求总预算。
