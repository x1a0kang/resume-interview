RAG
先从你自己的资料里找相关内容，再让 AI 根据找到的内容回答。
MCP
一种通用连接方式，让 AI 助手可以调用外部工具或知识库。
模型 / 大模型
负责理解文字、生成回答的软件；它本身不等于知识库。
API
软件之间互相请求服务的入口，可以理解成窗口或电话线路。
API Key
调用在线 AI 服务的密码；不要公开，也不要发给别人。
向量 / Embedding
把一段话转换成一串数字，方便电脑按“意思相近”寻找资料。
向量数据库
专门保存这些数字和原文，并按意思相似程度找资料的存储工具。

按问题里的词去找原文；常适合人名、术语、编号等明确词语。

同时用关键词查找和意思查找，再把结果合并。
Chunk / 文本块
把长文档切成一小段一小段，方便查找和引用。
RRF
把多种查找方式各自的排名合并；它不是准确率，也不是概率。
重排 / Rerank
先找出一批候选资料，再重新比较谁更相关。
分词
把句子拆成词，供关键词搜索使用。
入库 / Ingestion
把文件读出来、切成小段、保存好，让之后能搜索。

Tool / 工具

Large Language Model 的缩写，即“大语言模型”，负责读文字和写回答。

项目定位与源码范围

PaiSmart 是带上传、知识库、权限、会话与流式问答的完整企业知识产品。当前本地快照已包含双路并行召回、ReAct 工具循环、上下文检索、父上下文扩展、文件处理可靠性和评测模块。阅读结论以实现为准，不能用 README 中较早的简化流程代替当前源码。

最值得 HP 借鉴的是服务故障与数据一致性的处理机制。Kafka、WebSocket、ES 单库向量检索属于该项目的基础设施选择，迁移时可用 HP 既有 RabbitMQ、HTTP / 流式协议和 ES + VikingDB。

分块、Contextual Retrieval 与父上下文

能力实际实现与 HP 教材分块的差别
默认分块application.yml: chunk-size=512、overlap-size=100、min-chunk-size=100；先段落后句子，超长句用 HanLP，末尾片段与 overlap 有合并规则。属于文本边界启发式；HanLP 分词不能等同于教材教学单元识别。
PDF 定位LiteParse 产出页级文本，保存 pageNumber 与 anchorText。可借鉴解析定位；HP 对外稳定定位仍是版本、册次、章节，页坐标仅做内部 sourceLocator。
上下文检索默认关闭；每批 8 Chunk、邻居 2、窗口 6000 字符、说明 200 字符、并发 2。说明存 chunkContext，原文存 textContent。借鉴原文分离和有界并发；HP 先规则拼标题与结构，LLM 只处理低置信度片段。
表示一致Embedding 用 ContextualChunkText.compose；BM25 combined_fields 使用 chunkContext + textContent；Rerank 用同一 compose。HP 定义 RetrievalTextBuilder，三条索引 / 排序路径使用同一表示版本。
父上下文扩展默认邻居 1、每命中 1500 字符、总 6000 字符；按同文件相邻 Chunk 拼接，共享 parentKey 去重。这是邻接窗口，不是教学父子树。HP 按例题、图表、条件与方法关系扩展，同时借用预算和去重。

在线检索：带权限的双路召回

HybridSearchService.searchWithPermission

点击步骤可收起或展开说明。顺序表示调用与数据流。

BM25 在 bool.filter 中带权限，kNN 在 knn.filter 内带同一过滤。公开/组织权限是参考项目自己的模型，HP 必须换成学校、角色、资料授权与教材版本约束，父上下文回源也必须保留约束。

默认阈值来自该项目的场景，不能迁移成 HP 的“证据置信度”。归一化到 0～1 只是量纲换算，不是概率校准；RRF 与 Rerank 应分别评测和设阈值。

迁移前要理解的边界

  • 先删除再重建：FileProcessingConsumer 清理旧索引后重新解析，重建中可能出现不可检索窗口。HP 已规划“新版本构建后发布”，应保留该设计并补全双索引一致发布。
  • 哈希不是业务身份：ES ID 与回源按 fileMd5 / Chunk 序号组织；同一文件跨用户复用时，需审查权限、对象共享与 canonical 主键。HP 应独立 document_id、version_id 与 tenant 授权。
  • 父块权限假设：ParentContextExpander 认为文件级权限已在检索校验，并按 fileMd5 查询邻居。HP 有学校和版本约束，不能只用文件指纹回源。
  • 事后核查不拦截：引用核查失败或超时不影响回答，无法承担学生辅导输出前的强约束。HP 应区分生成前 Evidence Gate 与生成后的陈述检查。
  • 默认配置需验收：ES mapping 声明 isPublic，但检索构造公开过滤使用 public；布尔属性序列化可能生成 public。应检查实际 JSON 与 mapping，不能仅凭字段声明推断正确。
  • ACL 错误语义：search 的权限解析异常会返回 SearchTrace.empty；HP 必须区分身份 / 授权失败与真实无证据，并且任何降级都不能放宽权限。

我能在自己电脑上启动它吗？

可以，但这是完整网站，需要多个配套服务一起运行。除了前端网页和 Java 后端，还需要数据库、文件存储、搜索服务、消息队列和缓存。此电脑的 Node.js 22 与 pnpm 版本符合项目最低要求；Java 只有 8（项目要 Java 17），没有 Maven，Docker 的 Compose 命令当前也不可用，所以现在还不能直接启动完整网站。

推荐的 Windows 操作顺序：安装 JDK 17、Maven 3.8.6 以上版本和 Docker Desktop（带 Compose v2）；然后调整项目提供的容器配置文件。当前 infra.sh 写着作者 Mac 电脑的固定目录，不能直接在你的 Windows 电脑上用；docs/docker-compose.yaml 里的部分文件夹也写成 Linux 专用路径，需要先改成普通容器数据卷。
