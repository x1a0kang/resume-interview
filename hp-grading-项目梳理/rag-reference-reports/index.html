遇到陌生词？点这里看白话解释（不用背）
RAG
先从你自己的资料里找相关内容，再让 AI 根据找到的内容回答。
MCP
一种通用连接方式，让 AI 助手可以调用外部工具或知识库。
模型 / 大模型
负责理解文字、生成回答的软件；它本身不等于知识库。
API
软件之间互相请求服务的入口，可以理解成窗口或电话线路。
API Key
调用在线 AI 服务的密码；不要公开，也不要发给别人。
向量 / Embedding
把一段话转换成一串数字，方便电脑按“意思相近”寻找资料。
向量数据库
专门保存这些数字和原文，并按意思相似程度找资料的存储工具。
关键词检索 / BM25
按问题里的词去找原文；常适合人名、术语、编号等明确词语。
语义检索 / Dense
不要求字面完全相同，而是寻找意思接近的内容。
混合检索 / Hybrid Search
同时用关键词查找和意思查找，再把结果合并。
Chunk / 文本块
把长文档切成一小段一小段，方便查找和引用。
RRF
把多种查找方式各自的排名合并；它不是准确率，也不是概率。
重排 / Rerank
先找出一批候选资料，再重新比较谁更相关。
分词
把句子拆成词，供关键词搜索使用。
入库 / Ingestion
把文件读出来、切成小段、保存好，让之后能搜索。
MCP Server
提供工具的程序；AI 助手通过 MCP 与它通信。
MCP Host
运行 AI 助手并连接 MCP 工具的应用，例如某些桌面 AI 软件。
Agent
能根据情况决定下一步调用什么工具的 AI 程序。
Tool / 工具
Agent 可以调用的一项具体功能，例如搜索知识库。
Trace / 过程记录
记下一次提问经过了哪些步骤、用了多久、在哪一步出错。
LLM
Large Language Model 的缩写，即“大语言模型”，负责读文字和写回答。
OCR
把图片或扫描件里的文字识别出来。
Kafka / 消息队列
像待办事项传送带：先收下文件处理任务，后台再慢慢完成。
Redis
速度很快的临时数据存储，常放短期状态或缓存。
MySQL
常见的关系型数据库，适合保存用户、文件等结构清楚的数据。
Elasticsearch / ES
搜索引擎，擅长按关键词搜索并管理大量文本。
MinIO
像自建网盘一样保存文件的服务。
权限过滤 / ACL
先确认当前用户能看哪些资料，再展示搜索结果。
Outbox
把“数据库记录”和“待发送任务”一起保存，防止任务悄悄丢失。
租约 / Lease
有时限的任务占用权；处理者失联后，其他处理者可以接手。
幂等
同一任务重复执行，也不会重复写入或造成额外副作用。
Docker / 容器
把服务连同运行环境打包运行，减少手工安装步骤。
Maven
Java 项目的依赖安装和构建工具。
pnpm
JavaScript 项目的依赖安装工具。
Streamlit
用 Python 快速搭建网页操作面板的工具。
评测集 / Golden Set
人工确认过的一批问题和正确答案，用来比较系统改动有没有变好。
P95
把请求按耗时排序后，95% 的请求都不超过的时间；用于观察较慢情况。
Recall@K
正确资料有没有进入前 K 个搜索结果的比例。
MRR
正确资料在搜索结果里越靠前，分数越高的指标。
Prompt
给 AI 的指令和背景文字。
Token
模型处理文字时使用的计量单位；不严格等于一个汉字或一个词。
MongoDB
一种适合保存对话记录、过程记录等内容的数据库。
RabbitMQ
一种消息队列；项目用它把文件处理工作交给后台。
VikingDB
一种向量数据库；HP 方案考虑用它按意思搜索教学资料。
Cross-Encoder
一种逐对比较“问题和资料”的重排模型，通常比只看向量更细。
RAGAS
一套帮助检查 AI 检索和回答质量的评测工具。
Top-K
只取排名最前面的 K 条；例如 Top-5 就是前五条。
P0
优先级最高、建议先处理的事项。
Schema
约定数据里有哪些字段、字段叫什么、格式是什么。
JSON / YAML
两种常见的配置或数据文件格式；本报告里的命令和代码需按原样复制。
JDK
运行和编译 Java 程序所需的软件包；此项目需要 17 版。
IDE
写代码和启动程序的软件，例如 IntelliJ IDEA。
SDK
别人提供的一套代码工具，方便你的程序调用某项服务。
HTTP
浏览器和网站、软件和服务之间常用的通信方式。
WebSocket
一种保持连接的通信方式，适合实时逐段传输消息。
工作流 / Workflow
按预先设定的步骤执行的一套流程。
前端 / 后端
前端是浏览器里看到的网页；后端在电脑或服务器上处理数据和请求。
PPTX / DOCX
PowerPoint 演示文稿和 Word 文档的文件格式。
Baseline / 基线
比较优化效果时作为起点的原始版本。
Provider / 服务提供方
真正提供大模型、向量或其他服务的厂商或软件。
集合 / Collection
把同一类资料放在一起的一个资料组。
ID
一条记录的唯一编号，用来区分不同文件或资料段落。

最重要的结论

沿用已收敛的 ES BM25 + VikingDB Dense，先把 Office 原生解析、错误隔离、可靠入库与版本发布做成可运行闭环。检索质量上，把已有教学资料结构、查询改写与 Evidence Gate 变成有版本的组件契约和独立可评测的垂直切片。

MODULAR 帮你理解算法骨架，PaiSmart 帮你看到产品运行时的故障和状态；HP 需要自行验证教学单元与数学查询的增益。
